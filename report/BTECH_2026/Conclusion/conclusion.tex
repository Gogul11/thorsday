\chapter{\uppercase{Conclusion and Future Work}}
\label{chap:conclusion}

AgentOS demonstrates that planning, dependency-aware execution, context paging, scheduling, resource admission, bounded code execution, model routing, and frontend observability can be integrated into one multi-agent runtime. The implemented architecture connects the frontend, gateway, Python kernel, data stores, event transport, specialised agents, and model providers into a single execution pipeline. By separating planning, validation, scheduling, and runtime execution, the system makes agent workflows explicit, reusable, and observable rather than leaving coordination logic scattered across individual applications.

The evaluation provides evidence that these design choices are useful within the defined study conditions. Context retrieval achieved 98.0\% success on the synthetic set and 35.0\% on the LoCoMo pilot, planner evaluation achieved a 76.0\% exact tool-set rate across 50 trials, and priority aging reduced high-priority queue-wait $P_{95}$ by approximately 68\% in steady state and 78\% under contention compared with FIFO. Together, these results support AgentOS as a practical and transparent prototype for coordinating multi-step agent tasks, while the dataset scope, provider conditions, and controlled benchmark design limit broader generalisation.

Future work will improve durable recovery, execution checkpoints, coroutine restoration, permission policies, sandbox isolation, and hybrid routing. Evaluation should use production-like traces, varied provider conditions, held-out tasks, larger trials, and additional tool-use workflows.
