\chapter{\uppercase{Conclusion and Future Work}}
\label{chap:conclusion}

AgentOS demonstrates how planning, semantic agent selection, dependency-aware execution, context paging, scheduling, resource admission, bounded code execution, model routing, and frontend observability can be provided as shared services for multi-agent applications. The implemented system connects the Next.js interface, FastAPI gateway, Python kernel, Redis event transport, MongoDB task history, ChromaDB retrieval, specialised agents, and local/cloud model providers. Its structured plans, dependency validation, context management, priority-aging scheduler, resource checks, bounded code runner, and lifecycle events form one observable execution pipeline. Evaluation showed 98.0\% retrieval success on the synthetic context set and 35.0\% on the LoCoMo pilot, a 76.0\% exact tool-set rate across 50 planner trials, and reductions in high-priority queue-wait $P_{95}$ of about 68\% in steady state and 78\% under contention compared with FIFO. These results apply to the datasets, configurations, and instrumentation used in this study.

The implementation remains a prototype with cooperative scheduling, incomplete coroutine restoration after restart, and provider token usage that may be unavailable when metadata is omitted. The context and planner evaluations use limited datasets, and the scheduler benchmark uses deterministic workloads with stubbed persistence; the findings therefore do not establish production capacity or general superiority. Future work should strengthen durable recovery and execution checkpoints, add explicit permission policies and stronger isolation, and evaluate AgentOS with production-like traces, non-stubbed persistence, varied provider conditions, held-out conversations, paraphrased tasks, answer-level judging, and larger repeated trials. Additional tool-use scenarios and event-triggered workflows can further assess how well the architecture generalises.
